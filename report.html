2. Project Functionality (Point 1)

This project implements an automated, containerized personal portfolio web application built with plain HTML and CSS served via an Alpine Nginx web server. The codebase is version-controlled on GitHub following strict feature-branching conventions, containerized into lightweight Docker images, and governed by a continuous integration and continuous deployment (CI/CD) pipeline via GitHub Actions. Whenever commits are pushed or merged into the main branch, automated quality checks validate file integrity and metadata before building and publishing multi-tagged production containers to Docker Hub, while real-time lifecycle event notifications are emitted to an external webhook receiver.

Core Architectural Difference (Webhook vs. GitHub Actions):
A GitHub Webhook is a passive, outbound HTTP push notification system that serializes events into JSON and transmits them to external listening endpoints without performing any compute or execution itself. Conversely, a GitHub Actions Workflow is an active, fully integrated CI/CD execution engine running on provisioned virtual machine runners that interprets repository event triggers, clones the code, enforces custom validation gates, compiles container images, and automates deployments.

4. Real Problem Faced, Error Message, and Resolution (Point 4)

Problem Description: During the local manual Docker push and automated GitHub Actions publishing steps, the Docker CLI and docker-login-action@v3 failed authentication against Docker Hub, preventing image publication under the coffethebest/devops-a2 repository namespace.

Exact Error Messages Encountered:
Local CLI: Error response from daemon: Get "https://registry-1.docker.io/v2/": unauthorized: incorrect username or password
Actions CI: Error: buildx failed with: ERROR: failed to solve: failed to push coffethebest/devops-a2:latest: server message: insufficient_scope: authorization failed

Diagnosis & Resolution: Two root causes were identified: (1) an account name casing/spelling discrepancy between the GitHub handle (CoffeeTheBest) and the Docker Hub namespace (coffethebest), and (2) attempt to authenticate using interactive user credentials rather than a dedicated scoped token. To resolve this cleanly, a new Read, Write, Delete Personal Access Token (PAT: dckr_pat_...) was created in Docker Hub Security Settings. The secrets DOCKERHUB_USERNAME and DOCKERHUB_TOKEN were configured in repository Actions secrets via the GitHub CLI (gh secret set), and the local Docker daemon was authenticated using docker login -u coffethebest --password-stdin, immediately enabling successful multi-tag pushes for both manual and latest tags.
